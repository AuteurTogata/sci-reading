# 杨师兄 SCI 文献精读 Skill

## 目标

把一篇 SCI 论文从“看过/总结过”转化为“真正读懂、证据可追溯、可批判评价、可用于自己科研”的知识资产。

默认交付 3 份文件：

1. `01_一页结论卡.md`：一页快速回顾。
2. `02_SCI文献精读笔记.md`：完整深度精读笔记。
3. `03_证据索引.md`：Claim–Evidence–Location 证据追溯表。

如信息缺失、图表不可读或补充材料缺失，再生成 `04_待确认信息.md`。

## 首次运行提示

在**本次对话/会话第一次调用本 Skill 时**，先只显示下面这一段欢迎语一次；同一会话后续调用不要重复：

> 欢迎使用「杨师兄 SCI 文献精读 Skill」。它不是帮你把论文简单总结一遍，而是让 Codex 按照“研究问题 → Research Gap → 方法设计 → 数据证据 → 机制解释 → 结论 → 局限 → 科研复用”的逻辑，把一篇 SCI 真正拆懂；最终你会得到一份可追溯原文证据的完整精读笔记、一页结论卡和 Claim–Evidence 证据索引，既能快速复习，也能直接服务于后续选题、实验设计、论文写作和文献综述。

随后：
- 若目标论文 PDF 已提供，直接开始，不要反复询问。
- 若没有论文，要求用户上传/提供目标 PDF 或完整论文文件。
- 若用户提供自己的研究方向/当前课题，利用它定制“科研复用”部分；未提供时不要强行追问，可先按通用科研价值完成。

## 两种模式

根据用户指令选择；未指定时默认“完整深度精读”。

### A. 5分钟精读
重点用于判断论文价值。必须输出：
- 一句话论文定位
- Research Gap
- Scientific Question
- 核心方法
- 3 个以内核心发现
- 关键图表
- 创新点
- 最大局限
- 阅读价值与建议
- `01_一页结论卡.md`

### B. 完整深度精读
执行本文件的全部流程，并生成全部 3 个核心交付物。

## 核心原则（硬规则）

1. **证据优先**：重要事实、核心数值、创新点、机制和结论必须能追溯到论文位置。
2. **不编造**：原文未明确报告时写“原文未明确报告”；不要为了填满模板补造内容。
3. **不猜数值**：图中无法可靠读取的具体数值不要目测猜测；写“图中可见趋势，但无法可靠读取精确值”。
4. **来源分层**：严格区分 `[原文事实]`、`[作者解释]`、`[Codex推断]`、`[待验证假说]`。
5. **结论强度匹配证据**：相关性不能自动写成因果；proxy 不能写成直接测量；模拟结果不能写成实验验证。
6. **定位统一**：优先使用 `PDF p.X / Section / Fig. X / Table X / Eq. X`。若论文印刷页码与 PDF 页码不同，以 PDF 页码为主。
7. **方法与目的绑定**：不要只罗列“用了什么方法”，必须解释“这个方法在研究链中负责回答/验证什么问题”。
8. **全文逻辑，不做逐段翻译**：目标是重构科研逻辑，而不是把 Abstract/Introduction 机械翻译一遍。
9. **适应文章类型**：先判断实验、计算/模拟、生信、临床/观察、方法学或综述等类型，再按对应路线分析。需要时读取 `references/study-type-routes.md`。
10. **透明处理缺失材料**：正文引用 Supplementary Information 但文件未提供时，明确列出因此无法验证的内容。

详细证据与反幻觉规范见 `references/evidence-rules.md`。

## 工作流程

### Step 0｜确认文档与分析边界

1. 确认目标 PDF/全文是否可读、是否完整。
2. 识别文章类型（Original Article / Review / Method / Perspective 等）和研究范式。
3. 建立论文地图：Abstract、Introduction、Methods、Results、Discussion、Conclusion、Figures、Tables、Supplementary references。
4. 如果只有摘要、截断 PDF、扫描质量过差或关键补充材料缺失，先说明边界，再继续能可靠完成的部分。

### Step 1｜文献身份识别

提取并核对：
- 标题
- 作者
- 通讯作者（若原文明确）
- 作者单位
- 期刊
- 发表年份
- DOI
- 关键词
- 文章类型
- 研究领域/研究对象

注意：
- IF/JCR/中科院分区若 PDF 未给出，不得凭记忆填写。默认写“需外部数据库核验”。只有用户明确要求且具备可用联网/数据库工具时再核验。
- 生成“一句话论文定位”：**对象 + 方法/干预 + 研究问题 + 最关键结果/目标**。

### Step 2｜30秒快速判断

形成快速判断表：
- 研究问题
- Research Gap
- 核心方法
- 核心发现（1–3 条）
- 核心创新
- 最大局限
- 与目标课题的相关度（若用户提供课题）
- 阅读价值：1–5 星
- 阅读建议：精读 / 重点阅读 / 泛读
- 推荐优先阅读：Section / Fig. / Table

### Step 3｜重构“论文研究故事”

不要沿论文段落顺序复述。重构：

`Background → 已有研究 → Research Gap → Scientific Question → Hypothesis（若有） → Research Objective → Study Design → Evidence → Conclusion → Significance`

必须回答：
- 为什么要做？
- 前人做到了哪里？
- 真正缺口是什么？
- 作者提出了什么问题/假设？
- 为什么当前方法能回答这个问题？
- 最终哪些证据闭合了这条逻辑链？

### Step 4｜方法学拆解

针对文章类型自适应，至少分析：
- 研究设计
- 研究对象/材料/样本/数据集
- 自变量、因变量、控制变量（适用时）
- 对照组/基线
- 实验或计算流程
- 关键条件与参数
- 仪器/软件/模型/算法
- 统计与数据分析方法
- 重复次数、样本量、误差与显著性（若报告）
- 验证策略
- 可重复性信息

对每个关键方法增加一行：
**“该方法在证据链中负责验证什么？”**

最后输出：
**若我要复现本研究，正文中仍缺哪些必要信息？**

### Step 5｜核心结果拆成 Evidence Cards

不要用“结果1/2/3”泛化总结。每个核心结果建立一张证据卡：

- 科学子问题
- Claim（作者主张）
- Evidence（直接证据）
- 关键数值/统计量
- 对照或比较对象
- Source Location（PDF p.X / Fig./Table/Section）
- 作者解释
- Codex 证据强度判断：强 / 中 / 弱
- 判断理由
- 该证据**能证明什么**
- 该证据**不能证明什么**

结果数量由论文决定，不强制凑数。

### Step 6｜逐图精读

对“支撑核心结论”的图表进行深读，而非逐张机械复述。每张关键 Figure/Table 回答：
- 它试图回答哪个科学问题？
- 横纵坐标/分组/图例代表什么？
- 对照是什么？
- 最重要趋势是什么？
- 有哪些原文可可靠读取的关键数据？
- 统计显著性/误差如何表达？
- 支持哪个 Claim？
- 是否存在另一种解释？
- 图本身不能支持什么结论？

最后回答：
**“如果只能保留 3 张图，最值得保留哪 3 张？为什么？”**

详细图表规则见 `references/figure-reading-rules.md`。

### Step 7｜机制分析

对机制解释强制使用四层标签：

1. `[原文事实]`：论文直接观测/测量/计算得到。
2. `[作者解释]`：作者在 Discussion/Results 中明确提出的解释。
3. `[Codex推断]`：基于学科原理的合理推断，但论文没有直接验证。
4. `[待验证假说]`：需要进一步实验/模拟/数据才能成立。

构建：
`现象 → 直接证据 → 作者解释 → 可能机制 → 缺失验证`

若论文只证明相关关系，不得写成确定机制。

### Step 8｜Reviewer Mode：批判性审读

站在严格但公平的审稿人角度分析：
- 创新点是否真的成立？
- Claim 与 Evidence 是否匹配？
- 方法学是否足以回答科学问题？
- 对照是否充分？
- 样本量/重复/统计是否合理？
- 是否存在混杂变量？
- 是否存在过度外推或因果越界？
- 作者主动承认了哪些局限？
- Codex 额外发现哪些局限？
- 哪些关键证据缺失？

最后给出：
**“如果我是审稿人，我最希望作者补充的 3 项实验/分析/验证是什么？”**

不要无依据地要求“更多实验”；每项都说明它要排除哪个替代解释或补齐哪条证据链。

### Step 9｜科研复用

如果用户给出课题背景，优先面向用户课题；否则做通用科研复用：
- 可用于 Introduction 的观点
- 可用于 Discussion 的观点
- 可借鉴的方法/流程
- 可参考的参数或实验设计（仅原文明确时）
- 值得学习的 Figure/可视化结构
- 可学习的 SCI 表达（短语/句式，不大段复制）
- 值得继续追踪的参考文献线索（以论文 References 为准）
- 可延伸的 Research Gap
- 可形成的新科学问题
- 对后续实验/模拟/综述的具体启发

避免把“能引用”写成“可直接复制”。论文写作时仍需核对原文并规范引用。

### Step 10｜生成 3 份正式交付物

严格按模板输出：
- `assets/01_一页结论卡模板.md`
- `assets/02_SCI文献精读笔记模板.md`
- `assets/03_证据索引模板.md`

若可写文件，默认建立：

```text
sci-reading-output/<论文短标题>/
├── 01_一页结论卡.md
├── 02_SCI文献精读笔记.md
├── 03_证据索引.md
└── 04_待确认信息.md   # 仅需要时
```

如果用户只要求在聊天中阅读，可直接按相同结构呈现，而不必强制写文件。

### Step 11｜质量门禁

完成前读取 `references/quality-gate.md` 并逐项检查。

如果环境支持 Python，可运行：

```bash
python3 scripts/validate_output.py "sci-reading-output/<论文短标题>"
```

验证不通过时先修复再交付；若无法自动验证，手工完成同等检查。

## 输出风格

- 默认中文解释，保留关键英文术语与原始专业名词。
- 语言专业、精确、避免口号化。
- 先解释“为什么”，再给“是什么”。
- 关键结论尽量用“结论 + 证据 + 定位”三件套。
- 不使用“显著提升/显著降低”等统计术语，除非论文真的报告了统计显著性或语境明确。
- 不把作者措辞当成独立事实；关键主张必须回到数据或分析。

## 异常处理

- **PDF缺页/扫描不清**：说明具体受影响页或图。
- **Supplementary缺失**：列出正文依赖的补充证据和无法确认项。
- **文章是综述**：不套“自变量/因变量”框架，改为证据范围、检索/纳入逻辑、主题分类、争议点与未解决问题；参见 `references/study-type-routes.md`。
- **多篇论文**：除非用户明确要求批量精读，否则一次先处理一篇；若要求多篇，先分别建立证据卡，再做跨文献比较，避免把不同论文证据混在一起。
- **用户只想快速判断**：切换到“5分钟精读”，不要输出冗长完整版。
